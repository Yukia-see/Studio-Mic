# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Studio Mic is a Linux (PipeWire/WirePlumber, Arch/Omarchy-first) microphone processing and stream mixer (MOTIV Mix / Wave Link style). It's one Rust binary (`StudioMic-Package`, installed as `studiomic`, the one command for both the app and the CLI). It hosts an HTML UI in a WebKit webview and drives PipeWire by running its CLI tools. The spec it implements is `studio_mic_master_upgrade_spec_verification_checklist.md`. `AGENT_INSTRUCTIONS.md` and `concept-spec.md` describe the earlier HTML-only prototype. Their design rules still hold (summarised at the end of this file), but where they disagree with the spec or the code, the spec and the code win. Design decisions and deviations are in `docs/audit-report.md`, measured PipeWire behaviour in `docs/verified-apis.md`, and numbers in `docs/perf.md`.

## Commands

```bash
cargo build --release                  # app: target/release/StudioMic-Package
cargo build --release --workspace      # + tools/gap-probe, tools/latency-probe
cargo test --release --workspace       # unit tests (config migration, gain math, chain generation, sweep safety, probes)
cargo test --release <name>            # single test, e.g. legacy_migration_keeps_user_data
cargo run -- --background              # start in the tray (also --start-minimized, --tray, -b, --daemon)
./target/release/StudioMic-Package --help   # full CLI; e.g. --status --json [--runtime], --channel-gain "Capture Card" monitor +2dB
./target/release/StudioMic-Package --ui '<message>'   # inject a raw UI IPC message (scripting/tests)
./install.sh [-y] | sudo ./install.sh --system | ./install.sh --package     # see script header
# --package bumps packaging/BUILD_NUMBER (last successful build) and saves studio-mic-<Cargo version>-<N> in dist/<distro>/
./setup-deps.sh [--no-packages] [--stage DIR] [--vendor]                    # pinned LADSPA downloads
./target/release/gap-probe live --inject StudioMic_Ch_music --capture StudioMic_Stream_Mix   # dropout/click test
./target/release/latency-probe                                              # writes ~/.cache/studio-mic/latency.json
```

Running the app takes over the real audio session: it stops stale Studio Mic children, creates lingering buses and moves app streams. Only one instance per session can run (flock on `$XDG_RUNTIME_DIR/studio-mic/instance.lock`). CLI flags talk to the running instance over `~/.cache/studio-mic/studio-mic.sock`, falling back to `$XDG_RUNTIME_DIR/studio-mic/` when that path is too long. A CLI call starts a background instance if none is running.

## Architecture

**Process topology** (`src/audio/daemon.rs`, configs generated by `src/audio/filter_chain.rs` into `$XDG_RUNTIME_DIR/studio-mic/sm-*.conf`, PIDs in `~/.cache/studio-mic/pids.json`):
- **Tier-1 buses** `StudioMic_Voice_Out`, `_Stream_Mix`, `_VOD_Mix` (Audio/Source/Virtual) and `_Monitor_Mix` (Audio/Sink). The pre-v0.2 alias `studiomic_processed_mic` was removed; `ensure_buses` deletes any leftover copy. These are lingering null nodes in the main PipeWire daemon (`pw-cli create-node ... object.linger=true`, or the drop-in `pipewire-conf/60-studio-mic-buses.conf`). They're reused, never torn down.
- **Bus master** process: `StudioMic_<Bus>_Sum` → LSP stereo limiter (−1 dB, −3 dB monitor) → `StudioMic_<Bus>_Lim` → bus.
- **Mic chain** `StudioMic_Mic_g<N>_In/_g<N>` (a single stage, because each filter-chain hop costs latency): trim/mono-center mixer → denoiser → gate → HPF/LPF → de-esser → 10 EQ slots → compressor → Clipguard → split → route mixers. Outputs `AUX0..7` go to Voice/Stream/VOD/Monitor sums and `AUX8` is the meter tap. Voice_Out gets the main mic directly and, on request (`voice_routed`), Mic 2 and every channel except the voice-chat one (`is_comms()`, the echo guard: Discord would hear itself) through the `send:voice` stage. `relink_all` enforces this: anything feeding Voice_Out that isn't in `desired_links` is unlinked.
- **Channel strips** `StudioMic_Ch_<id>` (an Audio/Sink apps can target) → delays + Stream/VOD/Monitor mixers → `AUX0..5` + tap `AUX6`. Mic 2 is a similar strip with EQ.
- **Raw monitor** is a direct hardware → `StudioMic_Monitor_Mix` link, with no stage in between.
- **Send stages** `StudioMic_Send_<target>_In/_Out` (`spawn_sends_locked`, `fc::send_module`): one live stereo gain pair per source, with every output linked into the same target input, so PipeWire sums them (no in-graph mixer; builtin mixers stop at 8 inputs). Sources tap existing signal: a channel sink's `monitor_FL/FR`, the mic chain's `AUX8`, Mic 2's `AUX6`. `send:voice` feeds `Voice_Out_Sum`. Each custom mix (`custom_mixes`, routing matrix "+ Add Mix") is `send:<id>` → `StudioMic_Mix_<id>_Sum` → limiter → lingering `StudioMic_Mix_<id>` bus. Routing into a mix is only a gain (live); a stage restarts only when its source list changes (channel or Mic 2 added/removed, a channel's kind changes). Per-mix physical outputs (`mix_output_devices`, `CustomMixConfig.output_device`) are links from the bus's `capture_*` ports; `relink_all` only removes stale links into hardware sinks, never app links.

**Live-change rule (core invariant):** sliders, mutes and toggles never restart a process. They become `pw-cli set-param <id> Props { params = [ "node:Port" value ] }` written to one long-lived `pw-cli` child (`pw.rs` `PARAMS`), and `Engine::send` skips values that haven't changed. Stage on/off uses the LSP `Bypass` ports. Only a change in the *set* of EQ filter types or a denoiser switch is structural: `fc::fit_to_slots` maps a re-sorted band list (the UI sorts by frequency after a drag) onto the running slots, so reordering stays live. That calls `swap_mic_chain`, which builds generation N+1, waits until its links are `active` (`pw::wait_links_active`), crossfades the route gains, then retires N. Channel add, remove or rename restarts only that strip. Locks: `ops` serialises structural work; `swap_guard` is held for the whole swap and taken by `relink_all` and `apply_mixer` (so the Voice_Out firewall and ducking can't touch a half-swapped chain). Never take `ops` while holding `swap_guard`. Use `gap-probe` to prove any change to this path.

**Control flow:** `src/app.rs` `Controller` is the only thing that mutates state. Webview IPC (`handle_ui`, colon-delimited messages such as `mix:<ch>:<param>:<value>`), the socket CLI (`src/ipc.rs` accepts connections and forwards to `Controller::handle_cli`) and the tray (`src/tray.rs`) all call it. Webview messages are handed to a dedicated `ui-messages` thread (in order), never run on the GTK thread. The controller saves state, then enqueues coalescing `Job`s for a worker thread. Tray rebuilds and the Stream Deck state file are coalesced to at most one per 120 ms (`tray_dirty`), so don't push `UiPush::TrayRefresh` expecting it to be synchronous. Engine → UI events go through `UiPush::Js`, which evaluates `window.*` functions (`applyBackendState`, `updateChannelPeaks`, `updateRecorderState`, …). Changes that come from outside the UI call `sync_ui()`.

**Background loops** in `Engine`: maintenance every 2 s rebuilds stages that exited *or* whose sentinel node vanished (PipeWire restart), recreates buses, relinks, and runs app auto-routing. The other loops are ducking at 50 Hz (stream/VOD only, relative to each channel's gain; comms channels, a muted mic and preview are exempt), meter management (`pw-record` taps linked manually; see the meter note under Gotchas), the peak broadcast, a `pactl subscribe` two-way Monitor gain sync, and preview expiry. Graph queries (`pw::nodes/ports/links`) go through a 250 ms cache that's invalidated on every link or unlink.

**Stream Deck plugin** (`streamcontroller-plugin/com.studiomic.controller`, Python) speaks the same socket protocol as the CLI. Inside the StreamController Flatpak it falls back to running `studio-mic` on the host through `flatpak-spawn`. So any change to CLI arguments or output must keep `studiomic_client.py` working. `install.sh` copies the plugin into place. Distro packages are built from `packaging/arch/PKGBUILD` and `packaging/fedora/studio-mic.spec` (`./install.sh --package`).

**Routing** (`src/routing/wireplumber_hook.rs`): app streams are moved with `pw-metadata -n default <id> target.object <node.name>`, as a plain string (the JSON form silently fails). Per-channel `apps` lists plus preset rules decide the target. Studio Mic's own nodes (`StudioMic_*`, `node.group = studiomic`) are always ignored.

**State** (`src/config.rs`): `~/.config/studio-mic/state.json` with `schema_version`, 500 ms debounced atomic writes (`.tmp` → fsync → rename), and `flush_now()` on quit and signals. On first boot it migrates `~/.config/studiomic/config.json` (keeping a `.bak`). New fields need `#[serde(default)]`. Use `BTreeMap`, not `HashMap`, so restart diffs stay byte-identical. Devices are stored by `node.name`, never by numeric id. A missing saved mic shows as "Missing" and is never auto-replaced.

**Native UI (in progress)** is Slint: `ui/slint/app.slint` + `src/ui_slint/` (feature `ui-slint`, on by default), chosen with `--ui-backend slint|web` or `STUDIOMIC_UI`, else the saved `native_ui` setting (Settings → "Open the native window by default"; on by default, the webview stays available for one release, then wry/tao and the HTML go) (so far: studio strip, widget, Tab 1 matrix + Simple view, Tab 2 EQ, Tab 3 Fine-Tune (`tune.slint` + `tune.rs`, sends the whole `noise_clean:` config), Tab 4 Test & Optimize + the preview bar (`check.slint` + `check.rs`, recorder/preview state via `UiPush::Recorder` / `Preview`). Channel apps picker (`refresh_apps`: playing now + installed apps via `UiPush::InstalledApps`, `assign_app:` / `channel_apps:`). custom mixes rename by double-clicking their header (`mix_rename:<id>:<name>`, UI name only; the bus description in OBS updates when the bus is next created). Settings dialog (`settings.slint` + `settings.rs`: theme via `Theme.name`, autostart, start minimized, Mic 2, native by default, profiles save / load / delete, the last via the new `profile_delete:` message); EQ "My presets" (`save_user_preset:` / `delete_user_preset:`). Not ported yet: solo / autoduck / delays). `main.rs` creates either the Slint window or the tao loop (both need the main thread) and routes `UiPush` through one `UiSend`. The Slint side ignores `UiPush::Js` and uses the typed twins (`State`, `Peaks`, `Notice`, `MicMissing`, `Plugins`) that `app.rs` pushes next to each `Js`; actions are the same colon messages through `handle_ui`, and its `ui-messages` thread pushes `State` after each batch. Shared widgets are in `ui/slint/common.slint`, the matrix in `matrix.slint` + `src/ui_slint/matrix.rs` (`build()` ports `mxCell` / `mxLevel` / `mxSourceHtml`; cells and meters are flat row-major models updated in place, so a fader being dragged keeps its grab; device lists arrive as `UiPush::Devices`, app streams as `UiPush::LiveStreams`). EQ is `eq.slint` + `src/ui_slint/eq.rs`: RBJ biquad curve drawn by Rust at the graph's pixel size (a Slint `Path` keeps its aspect ratio, so a fixed viewbox would squash it); local bands win for 600 ms after an edit, then the saved state is shown sorted by frequency. Every size in the .slint is a multiple of `Theme.u`: in the main window it is just `ui_size` (the layout reflows to the window and what doesn't fit scrolls; an earlier fit-to-window shrink was unwanted); in widget mode one fixed layout (fader cards side by side, pills two across: 660 units wide, 162 + 32 per pill row high) is scaled to the window and centered in a card that covers the whole window (spare height widens the row gaps, capped), so nothing rearranges or flickers while resizing; keep `MainWindow.widget-scale` in step with `WidgetStrip`. Mixer has a Simple view (`mixer_simple`: a card per source with the My Mix and Stream cells, reusing the matrix cells) and the strip can collapse to one row (`strip_collapsed`); both are native-only state fields set with `mixer_view:` / `strip_collapsed:`. Icons use codepoints from `ui/material-symbols-outlined.codepoints` + the bundled TTF. Look at it without starting the engine: `SM_SNAPSHOT_DIR=/tmp/x cargo test --release snapshots -- --ignored` (offscreen PNGs, incl. 1.6x scale).

**UI** is `mic-studio-mockup.html`, compiled into the binary via `include_str!`, so a rebuild is needed after editing. The app never loads anything from the network: `build.rs` (`bundle_ui`) replaces the Tailwind CDN `<script>` with the prebuilt `ui/tailwind.css` and the Google Fonts link with the embedded `ui/material-symbols-outlined.woff2` (the source keeps both tags so it still opens in a browser). After adding new Tailwind classes, run `ui/build-css.sh` (Tailwind 3.4.17 via npx) and commit the regenerated CSS. Sliders: re-renders that replace or reset a range input go through `smDefer` (runtime script), which holds them while a slider is pressed and 250 ms after release, so backend echoes can't snap a fader back. The original script defines EQ, presets and calibration. A second "Studio Mic v1 runtime" script at the end of the file *redefines* the mixer, metering, theme, device, preview and DSP functions, so edit that one for those areas. Themes are CSS tokens under `:root[data-theme=...]`. Tab 1 is only the Wave Link-style routing matrix (`matrixHtml`, `mxCols`, `mxCell`); `view_mode` is always normalised to `"matrix"` and kept only so old state files parse. A new state starts with no channels (`default_channels()` is empty; existing files and the legacy migration keep theirs) and the matrix shows an empty-state card; the Add Channel modal has one-click presets (`AC_PRESETS`). The top bar is one studio strip (`#sm-strip`: mic dual-track fader on the input trim `calib_trim`, headphone fader on `monitor_gain_db` with the `bus:monitor` meter, generated quick-mute pills, DSP badges, app toggles); `smStatus(id)` gives every pill and mute ring its green / amber (≥ −6 dB or limiting) / red-only-on-real-clip (800 ms hold) / muted state. Control size is `ui_size` (`data-size` on `<html>`, CSS tokens `--sm-*`). Widget mode (`widget_mode`, `widget_width/height`, `always_on_top`; UI `toggle_widget_mode`, CLI `--toggle-widget` with `--toggle-view` as an alias, tray item) is `UiPush::Widget`: `main.rs` resizes, sets on-top and the title "Studio Mic Widget", and on Hyprland also floats/pins/resizes by window address with Lua dispatches (`hl.dsp.window.*`, falling back to the classic names); `body.widget-mode` shows only the strip. Matrix cells map onto `ChannelMix`: `stream_routed` / `monitor_routed` (right-click removes, `+` adds; separate from mute), VOD is the `vod` include toggle and always follows the Stream fader (spec), and Voice Chat takes the mic (always) plus any non-comms source (`voice_routed`), with `voice_gain_db` / `voice_muted`; a mic's Stream Mute stays its master mute and silences it in every mix. Custom-mix cells are `ChannelMix.sends[<mix id>]` (present = routed). `+ ADD MIX` creates a mix; `+ Add Channel` is a row under the matrix and on the Tab 1 toolbar.

## Gotchas found on this machine

- LSP limiters default to `Gain boost = 1`, which re-normalises output to 0 dBFS. Always set `"Gain boost" = 0` and `"Automatic level regulation" = 0` (a regression test covers this).
- `wpctl set-volume` is cubic. Use linear `channelVolumes` via `pw-cli set-param`.
- `pw-link` returns before a link is active. Wait for `state = active` before crossfading.
- To retire a stage, destroy its nodes server-side (`detach_nodes`) *before* stopping its process. Otherwise a slow-exiting client (DeepFilterNet) stalls the live cycle.
- An unlinked filter-chain isn't scheduled. It processes in its *input* node's callback. A fresh DeepFilterNet can stall the synchronous graph once in its first seconds. `node.async` fixes that, but costs ~24 ms of voice latency, so it's off (see `docs/perf.md`).
- Gate hysteresis is `filter_chain::GATE_HYSTERESIS_DB` (7 dB). The UI JS hard-codes the same 7 in the close-threshold label.
- Test tools that play tones (`gap-probe live`, `latency-probe`) must mute **and verify** `StudioMic_Monitor_Mix` before playing, and abort if they can't. Keep that guard. A broken test once played a loud tone into the user's headphones.
- Never match processes by substring of their command line. The stale-process sweep (`is_our_child`) matches the executable name plus exact args plus UID, because an earlier version killed the shell running a `grep`.
- Unix socket paths are limited to 108 bytes.
- The app needs the desktop session's `WAYLAND_DISPLAY`/`DISPLAY`: started from a shell without them, GTK init panics and the engine dies (CLI calls like `--status` also auto-start an engine). To restart it from a tool shell, copy those variables from a desktop process's `/proc/<pid>/environ`.
- 5.1 → stereo downmix happens in the *app's* stream adapter. Overs are caught by the bus limiters (the path is float), not by sink settings.
- There's no packaged Speex LADSPA wrapper on any distro, so Studio Mic has its own (`plugins/speex-ladspa/speex_ladspa.c`). `build.rs` compiles it if the speexdsp headers exist, and embeds it plus RNNoise (only if `setup-deps.sh` staged a SHA-matching copy in `assets/plugins/`, which is git-ignored). `src/audio/plugins_bundle.rs` writes missing ones to `~/.local/lib/ladspa` at startup. DeepFilterNet isn't embedded (~54 MB). It comes from `setup-deps.sh`, the packages, or `--download-deepfilter` / the UI button (pin duplicated in `daemon.rs`, and a test checks it matches `setup-deps.sh`).
- Meters must use `pw-record --raw` (see `meter_format_args`). Without it, pw-record writes an AU file to a pipe: little-endian on Arch, **big-endian on Fedora**, so every meter read garbage near full scale there (red meters, and auto-pad stepping the mic down at 1% volume). Measured in a Fedora 44 container (PipeWire 1.6.11). Test meter changes on Fedora too.
- Meters are `pw-record` at 48 kHz **f32**. The old 8 kHz s16 taps clamped and resampled, so audio limited to −0.5 dBFS read 0.0 dB (measured). The UI meaning lives in `smLevelState` (runtime script): strip meters show `out:<id>` (post-fader Stream send, i.e. what OBS gets), red means real distortion (`raw_clip`: the mic converter railing, detected as ≥6 identical full-scale samples in a row by `has_flat_top`, or overs with no LSP), and amber means a limiter is catching peaks or the mic input is within 1 dB of full scale ("HOT INPUT"). A level threshold alone is not clipping: software gain past 0 dBFS is still float and the limiters catch it. `bus:stream` / `bus:vod` meter the OBS buses directly.
- Without LSP, buses and Clipguard fall back to PipeWire's builtin `clamp` (`In`/`Out`, `Min`/`Max`). A wrong builtin port name fails *silently* (no error, the node outputs silence), so verify builtins by passing audio, not just by loading the config.

- A `pw-record` capture of a *sink* (`stream.capture.sink = true`, the `bus:monitor` meter) is never linked by WirePlumber if it also has `node.dont-fallback` or `node.dont-reconnect` (measured). And `relink_all` removes every Monitor_Mix output it didn't ask for, so it explicitly keeps links into `StudioMic_Meter_*`.
- Hyprland 0.53+ (Lua config, 0.56 here) takes `hyprctl dispatch "hl.dsp.window.float({ window = \"address:0x...\", action = \"enable\" })"`; the old `hyprctl dispatch setfloating ...` form is a Lua syntax error. `hypr_dispatch` in `main.rs` tries Lua first, then the classic name.

## Design rules (from the spec docs)

Material Design 3 with Material Symbols only (no emoji). Tab order: 1 Mixer, 2 EQ, 3 Manual Fine-Tune, 4 Test & Optimize. EQ has 1–10 bands, sorted by frequency. Presets are labelled "Recommended EQ for <Mic>". Gains are shown as dB · % (0 dB = 100 %), and a double-click resets to 0 dB. The mic is locked as the first card; other channels can be renamed.
